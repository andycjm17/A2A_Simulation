# Timing experiment v1: registered design

Decision: whether to keep decision rounds, and how to choose 5s, 10s or continuous trading. This is an offline scripted-agent experiment, not an LLM benchmark, network load test or deployed continuous market.

## 1. Existing engine controls

20 ordinary agents, one 20%-initial-tradable-cash maker, 10000 DUSD and 100 units of each asset per ordinary agent. Use the actual imported engine. Fixed-round control: 30 rounds at 5/10/60 seconds, identical seed, public news by round, policies and integer prices. With all decisions in time, assert identical trades and final cash, excluding timestamps. These matches have DIFFERENT elapsed durations, so do not interpret them as equal-duration volume comparisons.

Deadline sensitivity: assumed per-agent response delay 0.25/1/3/6 seconds plus a fixed per-agent 0-0.5 second offset. The engine closes orders at 90% of a 5s/10s round, or 55s in a 60s round. No live inference or API calls are measured.

Fixed-duration control: 300 seconds at 5s/60 rounds versus 10s/30 rounds. Resample the same 30-point fundamental path on a physical clock: news is published at 10s boundaries in BOTH conditions. Last public fundamentals are the common terminal prices. Production rules (one decision per asset/round, midpoint fills, per-round expiration, maker refresh each round) remain intact. This intentionally changes both trading opportunity count and maker refresh count, and does not isolate matching frequency alone.

## 2. Separate hypothetical scheduler: 3 x 3 factorial

Matching: 5s batch, 10s batch, continuous on arrival. Agent decision cadence: every 5s, every 10s, or event-triggered (public quote refresh/trade notifications, minimum 1s between requests, 10s heartbeat). Agent calls never overlap. Every call produces both-asset decisions, 8% PASS per asset, otherwise equiprobable buy/sell, 1-10 units. 40% fundamental, 40% noisy, 20% momentum, matching the earlier policy families; random draws are keyed by seed/agent/call-index/asset/field. The strategy uses current and previous PUBLIC fundamental, not future values or other agents' private decisions. Price noise/aggression and inventory constraints are as in the prior capital experiment.

All 9 cells share 300s duration, public news every 10s (35% shock probability per asset/epoch, 3-12% signed shock), asset paths, initial balances, 20% maker cash, maker refresh ONLY every 10s, 10s order TTL, one active ordinary order per asset, cancel-and-replace on a new decision. This differs from deployed per-round expiry/one-shot decisions, which is why production controls are reported separately. The full tape is held by the scheduler; policy inputs only contain released values. Fundamental clocks and maker funding cannot be altered by a treatment.

Main assumed response delay = 1s + fixed per-agent uniform[0,0.5)s, rounded UP to the 250ms scheduler grid. The 250ms grid is a simulation resolution, not a claim of zero-latency or tick-perfect realtime. Simultaneous arrivals use seeded random priority. Batch ties use seeded agent priority; continuous orders use price then arrival time then order sequence. At interval boundaries: auction the PRECEDING interval, expire old orders, publish news and refresh maker, deliver pending decisions, request new decisions. A final batch auction happens at 300s; requests arriving at or after close are excluded. Last prices are carried forward when no trades occur, explicitly retaining stale prices.

Continuous main fills use midpoint of crossing limits, holding pricing consistent with the production engine to focus on timing. An additional resting-order-price sensitivity addresses a common continuous order-book convention. It changes the pricing rule as well as the mechanism; do not attribute that combined effect to frequency alone. Maker side sizes: bid budget 10% cash per asset; ask 10% inventory; fundamental +/-1%, inventory skew capped +/-2%. No fees, borrowing, short sales or future information. Cancel releases collateral; each new order is clipped to free cash/inventory. Self trades are prohibited.

## 3. Outcomes and inference

Unit of replication = match/seed. Main = 200 paired seeds `timing-v1:0` through `199`, 9 factorial cells and 5 production-control cells per seed. Sensitivities = first 50 paired seeds, response delays 0.25/3/6s (all nine cells), and resting-price continuous execution (three cadences). Production deadline sensitivity uses the first 50 seeds, 3 delays x 3 periods. No outcome-based exclusions or stopping.

Primary outcomes: total executed units (counted once per fill), and time-average absolute last-trade-price deviation from contemporaneous public fundamentals, percent, sampled each 250ms for both assets. Exact lookup also reports ordinary mean final redeemed cash/return, excess return over the shared buy-and-hold allocation, completed calls, order count, maker volume share, matched-unit-weighted mean waiting time after order arrival (not inference delay), and fraction of executed units more than 2% away from the relevant fundamental. Cash ranking and terminal redemption remain the existing product rule. Return denominator = initial 30000 DUSD equity, not initial cash alone.

Planned contrasts: (a) 5s batch versus 10s batch at 5s decisions; (b) continuous versus 10s batch at 5s decisions; (c) continuous 5s versus continuous 10s decisions; (d) continuous event decisions versus continuous 5s decisions. For each, report paired difference, 95% paired bootstrap CI (10000 resamples), two-sided sign-flip p (19999 draws), Holm correction across 8 primary tests (4 contrasts x 2 metrics). Cash/returns/calls and all sensitivities are descriptive unless explicitly separately tested. No untested universal optimum claim. Confidence intervals concern the scripted model, not real LLM policy performance.

Validation: conservation and collateral/nonnegative balances on every 250ms tick and all actual-engine settlements; exact final cash transfer reconciliation against buy-and-hold; deterministic replay of all nine seed-0 cells; exact 30-round wall-clock invariance across 200 seeds. Unit tests exercise reservation across assets, resting/midpoint fills, self-trade exclusion, batch waiting, replacement, expiry, non-overlap and determinism. Keep code and raw per-match rows; the production Worker is not changed.
