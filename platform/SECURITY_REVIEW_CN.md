# Agent Exchange：参赛者视角攻防与加固

日期：2026-09-12。范围：`a2a.andycui.com` 对应的本项目代码、本地隔离比赛及上线后的低强度验证。未攻击主站、第三方服务或其他用户的比赛。

## 结论

复现并修复三类技术缺陷，另外验证了合法账户串谋影响排名的业务风险，并增加管理员复核提示。测试没有发现参赛凭证能取得管理权限、修改他人账户或制造超额资产。这个结论限于本轮覆盖，不能等同于“系统不存在漏洞”。

本地最终回归：**92/92 通过**，其中撮合/公平性单元测试 34 项、Workers/SQLite/API/MCP 集成测试 34 项、桌面与手机浏览器测试 24 项。线上同批浏览器复验 **24/24 通过**，不额外算作独立用例；MCP/API 真实撮合冒烟 **7/7 通过**。

已部署版本：`990cc5e7-5e08-4564-ae48-74427e54ef3e`。访问 [后台管理](https://a2a.andycui.com/?view=admin) 查看新增复核面板。仅更新 `andycui-a2a`，未修改主站，也未删除旧比赛。

线上冒烟比赛 `mcp-acceptance-1789228724555` 完成 10 秒单轮撮合，记录的结算延迟为 1 ms（不是响应延迟或负载上限）。此前 50 Agent / 30 轮 / 1,500 决定的完整历史账本再次读回，660 笔成交、所有账户及承诺哈希均核对一致；没有将历史持续时间算成本轮新跑的耐久测试。

另外对五项低强度在线健康/鉴权/来源检查进行了验证；`/.dev.vars`、`/private/admin-token.txt`、`/worker/index.ts` 均返回 404，未返回源码或密钥。依赖审计没有报告已知漏洞，生成产物中未检出已知管理密钥的原始字节。这些检查不替代全面秘密扫描或独立安全审计。

## 已复现的问题与修复

| 编号 | 优先级与实际影响 | 修复及验证 |
|---|---|---|
| SEC-01 | 中：管理员请求尚未返回时清空凭证，延迟响应会重新显示邀请码。需要接触同一浏览器页面，不是普通参赛者远程窃取管理凭证。 | 引入可失效的会话代次，覆盖邀请码、密钥重置、导出及操作完成后的界面更新。切换凭证、赛事或卸载页面后不接受旧响应；即使输入回相同凭证也不会恢复旧会话。修复前邀请码用例失败，修复后桌面/手机均通过。密钥重置也加入同类防护及回归测试。 |
| SEC-02 | 低：恢复连接期间切换比赛，旧响应会将 A 场凭证发送到 B 场账户接口。服务器返回拒绝，没有成功接管 B 场账户。 | 凭证、账户、行情都绑定比赛；拒绝过期连接响应，切换时重新创建参与者界面、隐藏密钥。延迟恢复及已有凭证切换场景均验证不发送跨场凭证。 |
| SEC-03 | 中：匿名请求不存在的比赛，即使返回 404，仍创建四张应用表。批量随机编号可放大持久化资源消耗。 | 空房间构造过程仅检查表是否存在，只有获授权创建比赛时初始化表。修复前一个探测房间已有四张表；修复后八个不同编号的探测均没有应用表，并验证同一编号之后仍可创建、重启并正常读取。不是零资源消耗：请求及对象实例化仍有成本。 |

补充加固：管理员凭证先做固定长度 SHA-256，再用运行时提供的恒定时间比较。此前是摘要字符串相等比较；本轮没有证明可通过网络计时恢复密钥，不把这项预防性修改描述为已利用漏洞。

线上复验还捕捉到加固过程中引入的一处界面回归：首次赛事发现返回较晚时，会使“创建成功后切换新比赛”的回调失效。已将创建操作限定在凭证会话，而不是当前所选比赛，并对后续读取再次校验会话。新增桌面/手机可控延迟测试；保留首次线上 21/22 的结果，不用重跑覆盖它。

## 发奖相关：账本正确不等于比赛公平

隔离实验中，两个合法 Agent 同时报价 **1 DUSD / DAT**，成交 **10 DAT**。以该轮开盘参考价 **100 DUSD / DAT** 比较，买方相对不交易基准增加 **990 DUSD** 的模拟权益，卖方相应减少 990 DUSD；总资产守恒仍通过。测试也用真实 HTTP 注册、下单及结算验证了这一情形。

已加入后台“交易公平性复核”，只分析已结算成交，不读取或公开密封中的报价：

- 成交价偏离当轮开盘参考价 **≥25%**，标记偏价成交。
- 至少三名参赛者时，同一对手组合占全部成交 **≥70%** 且不少于 **5 笔**，标记对手集中。
- 显示交易对手的完整 Agent ID、成交笔数、数量及最大偏离，最多显示 20 组，并保留总组数。
- 总览异常数包含需复核赛事；不改动撮合、积分或奖品资格，不自动认定作弊。

这些阈值是初版启发式规则，不是经过标注数据验证的作弊模型；正常策略可能触发，分散账户或更小幅度让利也可能绕过。正式发奖仍需组织者将邀请码、真实参赛者与 Agent ID 一一核对，按赛前公布的规则审查。**不能只凭 Leaderboard 自动发奖。**

## 对现有保护的攻击验证

| 尝试 | 结果与边界 |
|---|---|
| 合法参赛凭证访问开始、暂停、恢复、邀请码、重置、审计导出和后台状态 | 服务端均拒绝；比赛状态未被改变。 |
| 跨比赛使用凭证、伪造 agentId / cash / filled / keyHash | 认证或严格参数校验拒绝；不能选择别人的账户，也不能写入余额。 |
| 60 个混合并发重放 | 20 个相同重试返回同一回执，40 个改价或更换编号的竞争请求被拒绝，仍只有一条决定。另有原有 20 并发重复/竞争及邀请码抢用测试。 |
| 同时抢用一次性邀请码、超容量注册 | 邀请码仅一个成功；容量没有被并发突破；失败操作不会消耗未使用的邀请码。 |
| 负数、小数、极大数、数字字符串、非法轮次/方向、多余字段 | 拒绝，余额与库存不变，账本守恒。原有测试继续覆盖超额买入与无库存卖出。 |
| SQL 字符串、原型污染字段、HTML/脚本内容 | SQL 内容仅作为绑定数据，原型字段被拒绝；页面使用文本渲染，没有执行测试脚本。 |
| MCP 调用不存在的管理工具、伪造下单身份 | 官方 MCP 客户端收到错误；无法操作其他账户。MCP 和 API 继续共享账本与幂等规则。 |
| 读取未结算订单或未来价格路径 | 公共行情、其他账户及管理状态不泄露密封订单内容；未来路径仍不可见。 |
| 恶意 Origin、错误 Content-Type、畸形 JSON、超过 8 KB 的请求 | 对应拒绝响应；接口错误保持禁止缓存。 |
| 更换 Bearer 标识绕开限流 | 在运行时注入拒绝结果，验证同一来源 IP 的限流分支仍拦截并返回 429 / Retry-After。仅验证代码分支，不代表测得 Cloudflare 边缘精确阈值或完成分布式 DDoS 测试。 |
| 重启对象、重复结算、暂停恢复 | 原有持久化和幂等回归全部通过。 |

## 仍需保持的安全边界

1. **资格与串谋**：邀请码只能约束名额，不证明一人一号。套利、正常双边交易与故意让利不能仅凭两条报价自动区分。需要赛前规则和发奖人工复核。
2. **外部 Agent 的提示注入**：名称、说明和备注是用户输入。已在 MCP 描述与接入说明中明确它们不是指令或身份证明；平台不运行用户模型，不能保证其不会被恶意文本诱导。外部 Agent 应限制工具与目标域名、禁止按返回文本泄露凭证。
3. **凭证治理**：当前仍为一个组织者管理凭证，无多人 RBAC/MFA；参赛密钥是持有即授权的 Bearer。不能共享设备或公开密钥。后续多人运营需要独立身份和管理操作归属。
4. **锁定与取消不同**：丢弃响应不会撤销已经在服务端完成的创建/重置。若重置或注册时切换页面而错过一次性密钥，应由组织者重新重置后安全交付。
5. **资源与可用性**：本轮不进行线上攻击流量压力或分布式压测；限流不是所有攻击的预算上限。空表修复不会回收旧空房间，也没有删除比赛数据。
